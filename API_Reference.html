ADC Final — API Reference

Base URL (local): http://localhost:8080/rest  |  Base URL (deploy): https://adc-final.appspot.com/rest

Response envelope. Every response — success or error — returns HTTP 200. The real result is inside the JSON body, wrapped as { "status": ..., "data": ... }: 
// success           { "status": 200,  "data": { ... } }
// validation error  { "status": 9906, "data": [ { "status": 9930, "data": "INVALID_MESSAGE_TEXT" } ] }
// generic error     { "status": 9907, "data": "FORBIDDEN" }
Always check the status field — 200 = ok, any 99xx = error. In the examples below, the Response shows only the content of data. Authentication uses "token": { "jwt": "<jwt>" } in the body.

Request envelope. All endpoints wrap their domain fields under an "input" object, alongside the top-level "token" — e.g. { "token": {...}, "input": { ... } }.

Users

POST /createaccount public

Creates a new user account. confirmation must equal password; email must match algo@algo.algo.

Request
{"input": {
    "username":     "alice",
    "email":        "alice@mail.com",
    "password":     "Password123!",
    "confirmation": "Password123!",
    "category":     ["TECH", "COMMUNITY", "FOOD"],
    "role":         "USER"   // USER | BOFFICER | ADMIN
  }
}
Response
{"status": 200, "data": {"message": "Account created"} }
POST /login public

Authenticates a user and returns a JWT (valid 2h). Save data.token.jwt for all subsequent requests.

Request
{"input": { "username": "alice", "password": "Password123!" }}
Response

  "token": {
    "jwt":       "eyJhbGciOiJIUzI1NiJ9.eyJ...",
    "username":  "alice",
    "role":      "USER",
    "issuedAt":  1750000000,
    "expiresAt": 1750007200
  }}
}

Events

POST /events/create auth required

Creates an event (JSON). The organizer becomes the authenticated user; the event starts as UPCOMING with attendeeCount: 0. Images are added separately via /events/uploadimages.

Request
{
  "token": { "jwt": "eyJ..." },
  "input": {
    "title":           "Concerto de Jazz",
    "description":     "Uma noite incrível",
    "category":        "MUSIC",        // MUSIC|SPORTS|TECH|ART|FOOD|BUSINESS|COMMUNITY|OTHER
    "location":        "Lisboa",
    "startDate":       1760000000,    // epoch seconds
    "durationMinutes": 120,
    "maxAttendees":    50,            // 0 = unlimited
    "minAttendees":    0,
    "isPublic":        true,
    "isAccessible":    true,
    "sdg":             [ 8,15 ]
  }
}
Response
{"status": 200, "data": {
    "eventId": "550e8400-...-446655440000", "message": "Event created successfully" 
  }}

POST /events/attend auth required

Joins the authenticated user to an event. Public events register the user immediately (status: JOINED). Private events instead create a join request for the organizer to approve (status: PENDING) — like following a private account. Idempotent. Blocked if cancelled/completed/full, or if the organizer tries to join their own private event.

Request
{ "token": { "jwt": "eyJ..." }, "input": { "eventId": "uuid" } }
Response
{"status": 200, "data": { "message": "Successfully registered for the event", "status": "JOINED" }}
// public  event → "status": "JOINED"
// private event → { "message": "Join request sent", "status": "PENDING" }
POST /events/joinrequests auth required Organizer, ADMIN or BOFFICER

Lists the pending join requests of a private event, for the organizer to review (the "notification" side of the flow).

Request
{ "token": { "jwt": "eyJ..." }, "input": { "eventId": "uuid" } }
Response
{"status": 200, "data": {
  "requests": [
    { "requester": "bob", "requestedAt": 1759500000 }
  ],
  "count": 1
}}
POST /events/respondjoin auth required Organizer, ADMIN or BOFFICER

Accepts or rejects a pending join request for a private event. On accept, the requester becomes an attendee (and can then view the event) and the request is deleted. On reject, the request is marked REJECTED. Capacity (maxAttendees) is enforced on accept.

Request
{ "token": { "jwt": "eyJ..." },
  "input": {
    "eventId": "uuid",
    "username": "bob",
    "accept": true
  }}
Response
{"status": 200, "data": { "message": "Join request accepted" }}
// accept:false → "Join request rejected"

POST /events/uploadimages auth required Organizer or ADMIN · max 5 total

Uploads images to Google Cloud Storage and stores them on the event. Images are sent as Base64 data URLs. Each stored image is an { id, url } object — the id is unique (even for identical images) and is what you pass to /events/deleteimage.

Request
{
  "token": { "jwt": "eyJ..." },
  "input": {
    "eventId": "uuid",
    "images": [
      "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA...",
      "data:image/jpeg;base64,/9j/4AAQSkZJRgABAQ..."
    ]
  }
}
Response
{"status": 200, "data": {
  "imageUrls": [
    { "id": "a1b2c3", "url": "https://storage.googleapis.com/adc-final-events/uuid1" },
    { "id": "d4e5f6", "url": "https://storage.googleapis.com/adc-final-events/uuid2" }
  ],
  "message": "Images uploaded successfully"
}}
POST /events/uploadimageurls auth required Organizer or ADMIN · max 5 total

Attaches images that are already hosted URLs to the event — no Base64 decode, no GCS upload, just stored directly. Same 5-image cap as /events/uploadimages; blank URLs are ignored.

Request
{
  "token": { "jwt": "eyJ..." },
  "input": {
    "eventId": "uuid",
    "images": [
      "https://storage.googleapis.com/adc-final-events/foto1.jpg",
      "https://exemplo.com/foto2.png"
    ]
  }
}
Response
{"status": 200, "data": {
  "imageUrls": [
    { "id": "a1b2c3", "url": "https://storage.googleapis.com/adc-final-events/foto1.jpg" },
    { "id": "d4e5f6", "url": "https://exemplo.com/foto2.png" }
  ],
  "message": "Image URLs added successfully"
}}
POST /events/deleteimage auth required Organizer or ADMIN

Removes one or more images from the event by their id. The Cloud Storage file is deleted only if no other image entry still references the same URL — so removing one duplicate keeps the shared file for the others.

Request
{
  "token": { "jwt": "eyJ..." },
  "input": {
    "eventId": "uuid",
    "imageIds": [ "a1b2c3" ]
    // one or more image ids to remove (each is an imageUrls[].id)
  }
}
Response
{"status": 200, "data": { "message": "Image(s) deleted successfully" }}

Forum

Each event has its own forum (chat). Posts support threaded replies via parentPostId. Forums of cancelled/completed events are wiped by a cron job.

POST /forum/post auth required

Publishes a message in a forum. Any authenticated user can post (organizer not required). Blocked if the event is CANCELLED or COMPLETED.

Request
{"token": { "jwt": "eyJ..." },
  "input": {
    "id":           "uuid",
    "type":         "EVENT", // EVENT | FRIEND 
    "text":         "Alguém vai de carro?",   // 1..1000 chars
    "parentPostId": null      // optional: postId being replied to (thread)
}}
{"token": { "jwt": "eyJ..." },
  "input": {
    "id":           "joao",
    "type":         "FRIEND", // EVENT | FRIEND 
    "text":         "ja vistes o novo evento de football?",   // 1..1000 chars
    "parentPostId": null      // optional: postId being replied to (thread)
}}
Response
{"status": 200, "data": {
  "postId":         "9c2b-...-uuid",
  "eventId":        "uuid",
  "type":           "EVENT",
  "authorUsername": "alice",
  "text":           "Alguém vai de carro?",
  "createdAt":      1750531234,
  "parentPostId":   ""
}}
{"status":   200, "data": {
  "postId":         "6t3g-...-uuid",
  "friendId":       "joao",
  "type":           "FRIEND",
  "authorUsername": "alice",
  "text":           "ja vistes o novo evento de football?",
  "createdAt":      1750531234,
  "parentPostId":   ""
}}

GET /forum/cleanup cron only

Called automatically by App Engine cron (every 10 min). Marks ended events as COMPLETED and deletes the forums of completed/cancelled events. Rejected (FORBIDDEN) unless the request carries the X-AppEngine-Cron header.

Response
{"status": 200, "data": { "eventsClosed": 2, "postsDeleted": 17 }}

Typical Test Flow

  1. Call POST /createaccount — create a user
  2. Call POST /login — save the jwt from data.token.jwt
  3. Call POST /events/create — save the eventId
  4. Call POST /events/list — confirm the event appears
  5. Call POST /forum/post then POST /forum/list — chat on the event
  6. Create a second account, login, and call POST /events/attend
  7. With the organizer's token, call POST /events/attendees
  8. Call POST /logout — confirm the JWT is rejected afterwards

Error Codes

CodeMeaning
9900Invalid credentials (wrong password)
9901Username already exists
9902User or event not found
9903Invalid or revoked token (not logged in)
9904Token expired — please login again
9905Unauthorized — insufficient role / not owner
9906Invalid input (the data array lists the offending fields)
9907Forbidden — generic/unexpected error (e.g. editing a cancelled event, wrong old password, or a server-side exception)
9909Password does not match confirmation
9910Invalid role
9911 – 9923Invalid event fields (category, location, dates, duration, title, description, organizer, …)
9924Invalid email (empty or not matching algo@algo.algo)
9925Can't become friend with it self
9926Are already friends
9927Already sent friend request
9928Event already reached the maximum number of users
9929The structure of the json sent is not valid for that funcion
9930Invalid message text (empty or > 1000 chars)
9931Event not open for forum (cancelled/completed)
9932Forum post not found
9933SDG does not exist(n>17 || n<1)
9934You are not friends with this user
9935Partner already in the event
9936Partner not in the event
9937Forum origen is invalid (event not found) / (not friendship)
9938not enough SDGs
